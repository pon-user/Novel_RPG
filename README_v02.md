# 潮境の命珠 — 遊べるノベルRPG試作 v0.2

## ファイルの使い方

- **shiozakai_play_v02_single.html**：単独のHTMLファイル。ブラウザで開いて操作できます（CSS・データ・JavaScriptは全て同梱）。
- **index.html**：分割ソースの起点。`styles.css`, `app.js`, `battle.js`, `data.js`, `art.js`, `game-data.json` とともにHTTPSの静的ホスティングに置くと利用できます。GitHub Pagesが利用可能です。
- iPhoneでファイル表示から開いた場合、ブラウザやプレビューの仕様によってJavaScriptや端末内保存が制限されることがあります。継続的に試すときは通常のSafariでGitHub PagesのHTTPS URLを開く方法を推奨します。
- 自動同期・クラウドセーブはありません。進行状況はブラウザの`localStorage`（同一URL・同一ブラウザ）へ保存します。大きな戦闘ログの蓄積で保存容量に達する可能性があります。制作ノートからJSONバックアップを取得できます。

## 遊び方

1. **物語**：選択肢は初期状態で「未選択」。メイン（倉庫→呪い→双壁）、サブ（港の噂）、保留を選択できます。更新は試作版では「選択した行動を今すぐ更新」でのみ実行。19時自動判定は未実装。
2. **編成と戦闘準備**：主人公と仲間3人、装備3枠×4人、技能5R×4人を同じ画面で管理。キャラをタップして入れ替え、装備とラウンドのセルをタップして技能/装備を編集。**キャラアイコンや装備を長押し**すると図鑑詳細を開き、閉じると編成に戻れます。
3. **編成プリセット**：下部に3枠。保存してから「使用」で呼び出せます。編成・命珠・装備・技能予約を一括保存。
4. **ターゲットは自動判定**：戦闘前に敵人数・敵ID・敵ステータス・行動スクリプトを表示しません。計画にターゲットIDは保存されません。自動対象規則は編成画面の「技能の自動対象ルールを見る」から閲覧できます。
5. **戦闘後**：ログは全件表示が初期状態。プレイヤーが後で折りたたみ可能。戦闘結果・後日談まで時系列に表示。敗北時は「よし、シミュレーション完了！」の夢オチで同じ行動選択に戻ります。勝利時は次の幕へ進みます。
6. **図鑑**：キャラ、命珠、装備、敵、過去のストーリー・戦闘ログ。敵の未知行動は「???」。追憶は過去の敵と任意で再戦可能。

## 重要な戦闘ルール

- 主人公＋仲間3人（全20編成）、最大5R。Lv1、初期装備30種。
- 一部固有技能は1戦1回。未予約の技能は通常攻撃。編成変更時には元キャラと新キャラの装備3枠と予約を初期化。
- 味方の「挑発・庇護・広域護衛」だけ行動優先度＋1。その他は同一優先度内SPD順。
- 03/05はS5強化、敵⑤⑥はP1限定耐性、異なる能力対象群の正バフは乗算（例：1.45×1.35=1.9575）。07の浄化成功時に攻撃+20%、2行動。毒ダメージは対象の行動後。
- **③S9・④C13を採用**。EP-Bの二経路勝利案は未採用、5R以内の敵全滅だけを勝利条件とする。
- 04のMATK・06のPATK=130は、前回から引き継いだ試験基準値。正式ゲーム本体のマスタ確定ではありません。

## 試験について

- `node test_v02_engine.cjs`：敵17×仲間20編成、計340戦闘のスモーク、動的ターゲット・毒・技能基本予約を検証。
- `python test_v02_browser.py`：ブラウザで編成変更、長押し、装備、技能、プリセット、物語更新・図鑑を通し操作するテスト。
- `python test_v02_flow.py`：未選択更新、保留、E01勝利→E04未準備敗北の夢オチ、ログ表示、戦闘記録保存を検証。
- ブラウザ自動テストではネットワークへのナビゲーションが制限されたため、単一HTMLを`page.set_content()`でロード。実機SafariとGitHub Pages公開URLでの最終動作確認は未実施。
- 戦闘はv11/v13 Python試作を参照した**独立JavaScript移植**であり、数値・状態失効・戦闘AIの完全同値性は未保証。旧版のターゲット指定廃止により、以前の勝率や攻略例はそのまま再現されないことがあります。
